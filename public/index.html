Week 15 Foundation

Node.js Runtime & CommonJS Module System

Learn how Node.js allows JavaScript to break out of the browser and execute directly on the operating system.

What is the Node.js Runtime?

Node.js is an open-source, cross-platform JavaScript runtime environment that executes JavaScript code outside a web browser.

  • V8 Engine: Compiles JavaScript directly into machine code for high performance.
  • libuv Library: Provides the event loop and thread pool for non-blocking asynchronous I/O.
  • Single-Threaded Event Loop: Handles thousands of concurrent network connections without allocating heavy operating system threads per request.

Browser JS vs Server-Side JS

Feature Browser JavaScript Node.js (Server-Side)
Global Object window, document global, process
Filesystem Access Restricted (Sandbox) Full access via fs
Operating System Inaccessible Direct access via os, process
Primary Role UI, events, DOM rendering APIs, databases, business logic

Node.js Core Modules: fs, path, and process

Node.js ships with powerful built-in modules that require no npm installation. Explore how they enable real backend capabilities.

Working with Files: fs.promises

Node's fs module provides asynchronous, non-blocking file operations. Always prefer fs.promises with async/await in modern backend applications.

Asynchronous File I/O Pattern 
const fs = require('fs').promises;
const path = require('path');

const filePath = path.join(__dirname, '..', 'data', 'notes.json');

// Reading data asynchronously
const raw = await fs.readFile(filePath, 'utf8');
const notes = JSON.parse(raw);

// Writing data safely
await fs.writeFile(filePath, JSON.stringify(notes, null, 2));
Safe Storage Guarantee: All notes are stored inside data/notes.json in this project. No arbitrary files or unsafe user paths are allowed.

The path Module: Cross-Platform Path Handling

Operating systems handle file paths differently: Windows uses backslashes (\), while Linux and macOS use forward slashes (/). The path module normalizes paths automatically.

path Methods Reference 
const path = require('path');

path.join('users', 'docs', 'file.txt'); // Cross-platform safe join
path.resolve('file.txt');               // Resolves to absolute path
path.basename('/data/notes.json');      // 'notes.json'
path.extname('/data/notes.json');       // '.json'
path.dirname('/data/notes.json');       // '/data'
Never hardcode slashes: Using 'folder/' + file will break on Windows. Always use path.join(__dirname, 'folder', file)!

The process Global Object

The process object provides information about, and control over, the current Node.js process. It is globally available without require().

  • process.version: Node.js runtime version.
  • process.platform: Host OS (win32, linux, darwin).
  • process.arch: Processor architecture (x64, arm64).
  • process.cwd(): Current working directory of the process.
  • process.env: Access to environment variables.
  • process.uptime(): Seconds the current process has been running.
  • process.exit(code): Terminates the process with an exit status.

Environment Variables & .env

Environment variables allow configuration to be separated from code (The Twelve-Factor App methodology).

Using dotenv in server.js 
// 1. Install: npm install dotenv
// 2. Load at the very top of server.js
require('dotenv').config();

// 3. Access securely
const PORT = process.env.PORT || 3000;
const NODE_ENV = process.env.NODE_ENV || 'development';
Security Best Practice: Never commit .env files to git. Always add .env to .gitignore and commit a safe .env.example template instead!
Pure Node.js

Building a Server with the Native http Module

Before Express existed, Node developers built web servers using the built-in http module. Explore how it works at the lowest layer.

How http.createServer() Works

The native http module uses an event-driven HTTP parser that invokes a callback function on every incoming request.

raw-server.js snippet 
const http = require('http');

const server = http.createServer((req, res) => {
  const { method, url } = req;
  
  if (method === 'GET' && url === '/api/hello') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ message: 'Hello from Raw HTTP!' }));
    return;
  }
  
  // Manual 404 handling required
  res.writeHead(404, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ error: 'Not Found' }));
});

server.listen(3001);
  • req (IncomingMessage): Readable stream containing HTTP method, requested URL, headers, and body stream.
  • res (ServerResponse): Writable stream used to send status codes, response headers, and write the body payload.
  • res.writeHead(status, headers): Sends HTTP status code and header block to the client.
  • res.end(data): Signals to the server that all response headers and body have been sent.

    1. req (Request Object)

    Represents the HTTP request and has properties for the request query string (req.query), parameters (req.params), body (req.body), and HTTP headers (req.headers).

    2. res (Response Object)

    Represents the HTTP response that an Express app sends when it gets an HTTP request. Methods include res.status(), res.json(), res.send(), and res.setHeader().

    3. next() and next(err)

    Calling next() passes control to the next middleware function in the stack. Calling next(error) with an argument skips all remaining standard middleware and jumps straight to the 4-argument error handler.
